# 信源扩充与 PR 流程（天信每日日报）

> 本文件是「日报信源清单如何演进」的唯一权威流程。当每日运行时发现**清单未覆盖的有效信源**（新的采购平台、县区入口、框架协议征集渠道等），按本流程处理：**验证 → 改清单 → 自测 → 提交 PR**，然后由负责人 review 合并。
>
> 关联文件：`references/信源清单.md`（信源本体 + 附录 B 有效性自评）、`references/招标商机处理规范.md`（商机加工与核验门禁）、`SKILL.md`（每日工作流入口）。

---

## 一、什么情况该提 PR（触发条件）

满足**任意一条**即应发起信源扩充 PR：

| 触发 | 例子 |
|---|---|
| **A. 命中清单外信源** | 抓取中发现某县/某平台发布的会计审计类公告，其域名不在清单内（如本次发现宁海单在 `ccgp-ningbo.gov.cn` 也发布） |
| **B. 现有信源结构性抓不到** | 地域范围扩展后（如新增周边县市嵊州/新昌/宁海），原有台州平台**物理上抓不到**，必须补跨市入口 |
| **C. 现有信源长期低产或失效** | 连续多日某个源 0 命中、或返回 403/404/空页且无替代抓法 |
| **D. 发现"入场券"级渠道** | 某县市会计/审计**框架协议库**（天信未入库）的征集公告渠道，属高价值 |
| **E. 抓取方式需要修正** | 某站从"WebFetch 可抓"变成"必须 WebSearch 限定域名"（或反之），导致长期空转 |

**不该提 PR 的情况**（避免噪音）：
- 只是想多抓一次同一信源（属于当日检索策略，不是清单变更）；
- 第三方聚合站（剑鱼、千里马等二手转载），见信源清单附录 B1；
- 超出服务半径的市本级大单站点（绍兴/宁波市本级除外，其辖县已覆盖时按 A 处理）。

## 二、四步流程

### 第 1 步 · 验证（必做，不得凭印象）

新信源必须**实测通过**以下三项，缺一不可：

| 验证项 | 通过标准 | 记录方式 |
|---|---|---|
| **V-1 可抓取** | 实际用 WebFetch 或 WebSearch 限定域名拿到**真实公告标题 + 日期 + 链接**（不是登录页、不是"暂无数据"、不是空壳） | 记下抓取方式、实测日期、样例公告标题 |
| **V-2 有货** | 该源在**天信业务范围**（会计/审计/绩效/代理记账/竣工决算/资产评估/税务/咨询）内近期**至少 1 条真实商机** | 贴 1 条样例（项目名 + 日期 + 金额或截止） |
| **V-3 不重复** | 与现有信源比对：是否**已被覆盖**？若完全重叠，只作"交叉验证"标注，不新增条目 | 写明与哪个现有源重叠 |

> ⚠️ **不要因为"看起来相关"就加**。一个源加进去意味着每天都要跑一次，低产源会持续消耗轮次。宁可少加、加准。

### 第 2 步 · 改清单

只改两个文件，**不要动 SKILL.md 的信源正文**（SKILL.md 只留调用入口与摘要，细节归 references）：

1. **`references/信源清单.md`**
   - 在正文章节追加（编号沿用现有体例，或用「附录 A」体例）
   - 每条**必须**写全：站点名 / 地址 / **抓取方式（WebFetch 还是 WebSearch 限定域名）** / 内容范围 / 实测结论（含日期）/ 已知坑
2. **`references/信源清单.md` 附录 B 有效性自评表**
   - 新增行，填「实跑成色 / 主要问题 / 处置建议」，成色未知写"待观察"

若涉及**地域范围**变化（如本次周边县市），须**同时**改 `references/招标商机处理规范.md §〇之三` 与 `SKILL.md` 的「筛选逻辑」地域优先级，三处口径必须一致。

### 第 3 步 · 自测（本地跑通再提）

```bash
cd <repo>
# 1) 语法/引用完整性：清单里出现的文件路径都存在
ls references/ && grep -o '`[a-z_/.-]*\.md`' references/信源清单.md | sort -u

# 2) 自检脚本仍可运行（不应因文档改动而报错）
node references/check-dashboard.js daily/latest.html   # 有当日看板时

# 3) Markdown 基本健全：代码围栏成对（用 python 统计，避免命令示例里的三引号干扰计数）
python3 -c "import sys;n=open('references/信源清单.md',encoding='utf-8').read().count(chr(96)*3);print(n,'OK' if n%2==0 else 'ERR')"
grep -n '{{\?\?' references/信源清单.md || echo "无占位残留"
```

- 若本次 PR **同时改了规则**（如核验门禁），须附一次**回归证据**（例：拿历史错误样本跑自检，证明能被拦下）。
- 文档类 PR 不要求跑全量抓取，但**验证样例必须是真实抓取结果**，不得编造。

### 第 4 步 · 提交 PR

**分支命名**：`chore/sources-{要点}-{YYYYMMDD}`，例：
- `chore/sources-radiation-area-20261103`
- `feat/verify-gate-20261103`

**提交信息**：首行说清"改了什么 + 为什么"，正文列验证证据。

```bash
git checkout -b chore/sources-radiation-area-20261103
git add references/信源清单.md references/招标商机处理规范.md SKILL.md
git commit -F - <<'MSG'
信源扩充：纳入嵊州/新昌/宁海周边县市 + 新增绍兴库/宁波库入场券信源

背景：
- 天台县位于台州最北端，与绍兴嵊州/新昌、宁波宁海相邻；按行政边界划商机范围对本所不合理。

变更：
- 信源清单新增附录 A（A1 浙江政采网按县筛 / A2 绍兴市框架协议 2025-12-0006,0007 /
  A3 宁波政采网 / A4 宁波市框架协议 NBZFCG2025077K）
- 新增附录 B 信源有效性自评（逐源成色 + 待评估不纳入清单）
- 招标商机处理规范新增 §〇之三 地域优先级规则；SKILL.md 地域优先级同步

验证：
- 浙江政采网实测命中三县真实公告（列表自带 [ 嵊州市 ]/[ 新昌县 ]/[ 宁海县 ] 地区前缀）
- 绍兴市财政局 2026-02-06 已定 65 家入围（含嵊州/新昌采购人范围）
- 宁波市框架协议 NBZFCG2025077K 已入围含宁海德祥（宁海本地所）
MSG
git push -u origin chore/sources-radiation-area-20261103
```

**建 PR**（三选一，按环境可用性降级）：

| 方式 | 命令 | 适用 |
|---|---|---|
| ① `gh` CLI | `gh pr create --base master --head <branch> --title "..." --body-file pr-body.md` | 本机已 `gh auth login` |
| ② git 凭据 + API | 用 `GITHUB_TOKEN` 调 `POST /repos/{owner}/{repo}/pulls` | 云端 agent（有 token 但无 gh） |
| ③ 降级 | 推送分支后，把 `https://github.com/<owner>/<repo>/compare/master...<branch>?expand=1` 贴给负责人点击创建 | 无 token 写权限 |

> **PR 正文模板**（必含四段）：`背景 / 变更 / 验证证据 / 风险与回滚`。
> 回滚一句话即可：`git revert <merge-commit>`，文档类改动无数据影响。

## 三、PR 的纪律

- **一次 PR 只做一类变更**：不要"顺手"把当日报纸内容、推送逻辑、信源扩充混在一个 PR 里。
- **不改别人正在用的东西的语义**：新增信源用「追加」，不要重排既有编号（会导致日报运行记录里的引用失效）。
- **不改 `daily/` 产出**：那是运行结果，不是配置。PR 只动 `references/`、`SKILL.md`、`templates/`、脚本。
- **不提交凭据**：`push-secrets.json`、token 一律不入库（已在 `.gitignore`）。
- **必须能说清"这个源能带来什么单"**：说不清就不加。
- **合并前负责人 review**：信源扩张会改变日报口径（多了哪类单、少了哪类），须负责人确认符合所里获客方向。

## 四、Agent 自动执行的边界（重要）

日报运行时（云端/自动化）**可以做**：
- 发现清单外信源后，完成第 1 步验证、第 2 步改文件、第 3 步自测；
- **推送分支并创建 PR**（若环境有写凭据）；
- 把 PR 链接贴进当日「运行记录」并告知负责人。

**不可以做**：
- ❌ **直接 push 到 `master`**（必须走 PR，留 review 痕迹）；
- ❌ 自行合并 PR；
- ❌ 用未验证的源去改写当日日报结论（新源在 PR 合并前，当日日报仍按旧清单执行，避免口径漂移）。

> 若环境无写凭据（如某些云端沙箱）：**不要伪造成功**。把改动写成 patch 文件或直接给出 `git diff`，连同验证证据一并交付给负责人，并明确说明"未推送，需本机执行 `git push`"。

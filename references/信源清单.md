# 信源清单（天信每日日报 · 已验证 · 2026-11-03 重构）

## 本清单的用途与使用规则

- **用途**：天信每日日报的抓取信源登记簿。所有信源必须先在此登记并验证，才可进入每日抓取流程；信源增删改走 `references/信源扩充与PR流程.md`，不得绕过流程直接改清单。
- **分层结构**（不混排）：
  - **一、每日必检**：每期日报必跑，漏跑即漏收；
  - **二、机会型**：交叉验证与补充，按需跑；
  - **三、周期性 / 事件触发**：不占每日轮次，命中事件才处理；
  - **四、参考入口**：不抓取，适时提醒用；
  - **五、已失效 / 已停用**：保留记录与失效原因，**不得使用**。
- **统一字段**（每条信源固定 7 项）：
  | 字段 | 含义 |
  |---|---|
  | 入口 URL | 真实可用入口（直抓地址 / 接口地址 / 限域检索域名）；标 ⚠ 的为不可直抓入口，仅作标识 |
  | 抓取方式 | WebFetch 直抓 / WebSearch 限域 / `references/fetch-rendered.py` 及其所走的降级级别 |
  | 时效窗口与翻页 | 每日取多少条、翻页方式及其已知边界 |
  | 覆盖公告形态 | 招标公告 / 招标文件公示 / 采购意向 / 中介竞价 / 结果公告等 |
  | 优先级 | 必检 / 机会型 / 周期性 / 已停用 |
  | 上次验证 | YYYY-MM-DD + 一句实测结论（证实与证伪同样要记） |
  | 备注 | 实测教训、参数边界、与其他信源的交叉关系 |
- **登记规则**：
  1. **谁加**：维护者经 PR 增改（流程见 `references/信源扩充与PR流程.md`）；
  2. **要填哪些字段**：上述 7 项全填，缺一不得登记为"必检"；
  3. **验证到什么程度才算登记成功**：必检信源须**实测抓到 ≥1 条真实条目**（标题 + 发布日期 + 详情链接 / articleId 等价物）并记录验证日期；接口类还须验证参数边界（如页大小上限）；**只写名字没写抓取方式、或未实测的，一律标「待验证」放在备注，不得进入必检组**。

> **抓取方式总则**：能直接 WebFetch 的用 WebFetch；被反爬/JS 拦截的站，**必须用 WebSearch 限定域名**才能稳定拿到真实公告。二者不可混淆。⚠ 实测（2026-11-03）：WebSearch 的域名限定过滤并不严格（限定 `zfcg.czt.zj.gov.cn` 时仍返回 `ggzy.tzztb.zjtz.gov.cn` 等其他域名的结果），**命中条目必须逐条核对域名**，不得默认全部来自限域站点。
>
> **天台县优先**：天台县为天信驻地，所有信源检索须额外叠加 `天台` 关键词单独检索一遍（代理记账/财务审计/会计服务/绩效评价/竣工决算），板块一「天台县专项」子区数据来源于此。

## 〇、检索操作规范（模板与硬规矩）
- **招标/采购类检索**（N2/N3/N6、O1/O2、附录 A 各源）：检索词固定叠加 `招标公告`，并排除结果类词 `结果|中标|成交|候选人|合同`——死单常占检索结果一半以上，检索阶段就过滤，不进候选池再人工判死（2026-11-03 实跑实证：候选约 10 条中 7 条为死单，核验阶段过半功夫花在判死上）。
- 例外：采购意向公开、中介竞价、框架协议征集等非「招标公告」形态的检索不加 `招标公告`，但结果类排除词照用。
- 🔁 **公示形态各自单独检索一遍（实测教训：一江山跟踪审计单就漏在「招标公告」形态之外）**：`招标文件公示`、`预公示`、`采购文件公示`、`意见征询` 这四种形态与「招标公告」标题互斥，固定叠加「招标公告」的检索式撞不上它们——上述检索跑完后，这四种形态**每个单独叠加关键词再检索一遍**，结果类排除词照用。
- ⚠️ **公示形态的有效性判据不同（不得混用）**：招标文件公示/预公示/意见征询类公告的截止字段是**「公示截止」**（提意见窗口，通常 3-5 天），**不是「投标截止」**——公示结束≠投标开始，更≠失效。这类单的有效性判据走「发布日期 + 公示期 + 原文链接」三件套（见 `招标商机处理规范.md §〇之二`）；门禁的截止过期拦截只认「截止/开标」字段上的日期，公示期日期不参与，两边口径已对齐，改判据时必须两处同改。
- 🔴 **列表命中必留 articleId（硬规矩）**：浙江政采网等列表页命中条目时，**当场留存 articleId 与完整 URL**（详情页 URL 里的 `articleId=` 参数），供 L1 接口 `portal/detail?articleId={id}` 直取正文与 `expiredAt`（具体用法见 `反爬与渲染页抓取.md` 政采云小节）。**只记标题不记 articleId 导致的正文断链，视为抓取失败而非"未命中"**（实证：2026-11-03 温岭一院 11 月采购意向因未留 articleId，品目三轮检索均不可得，前瞻窗口断链）。省平台列表的等价物是 **infoid**（接口返回字段，见 N1），同样必留。

### N1. 浙江省公共资源交易服务平台 · 招标文件公示栏目【必检 · 前瞻窗口】

- **入口 URL**：
  - 站点首页：https://ggzy.zj.gov.cn/
  - 栏目真实入口（SPA 路由，可渲染）：`https://ggzy.zj.gov.cn/jyxxgk/list.html?cate=工程建设&catenum=002001&mycatenum=002001011`
  - 数据接口（首选直连）：`POST https://ggzy.zj.gov.cn/inteligentsearch/rest/esinteligentsearch/getFullTextDataNew`

- **抓取方式**：`references/fetch-rendered.py` 第二优先通道（接口直连，实测通过）：
  `python references/fetch-rendered.py "https://ggzy.zj.gov.cn/jyxxgk/002001/002001011/" --kw 跟踪审计`
  （`--kw` 关键词检索、`--days N` 时间窗，默认 7 天）。接口参数：**`time` 控时间范围**（`fieldName:webdate` + `startTime`/`endTime`）、**`wd` 控关键词**、条目 ID 为返回字段 **infoid**（**必留**，§〇 硬规矩）。payload 格式经 Playwright 请求拦截实测捕获（2026-11-03）。降级链：接口直连 → Playwright 渲染 SPA 路由（实测通过，16 条/页）→ agent-browser → Chromium（fetch-rendered.py 内置）。
- **时效窗口与翻页**：每日第一页（最新 16 条）+ `--kw` 关键词检索。**实测边界**：接口 `rn` 放大到 100 被服务端静默返回空（须 rn=16）；**翻页结果集不稳定**（total=83 只去重出 25 条）——**跨日回溯勿依赖翻页**。
- **覆盖公告形态**：招标文件公示 / 预公示（**尚未开始投标的前瞻窗口**：招标文件定稿公示后才发正式招标公告，比招标公告早数天露出，公示期内可提意见——对跟踪审计/决算审核类标的最有价值）。
- **优先级**：必检（2026-11-03 纳入，非机会型）。
- **上次验证**：2026-11-03——`--kw 跟踪审计 --days 5` 精确命中一江山跟踪审计公示单（2026-10-30 18:42:21 发布），条目详情 URL 与看板原文链接逐字一致；此前该单仅靠 WebSearch 兜底捞到。重构抽查（同日）复现：接口直连命中同一单，infoid/详情 URL 齐全。
- **备注**：省级平台汇聚台州各县市区标的，可捞到**浙里招标站内容易漏掉的天台县工程审计类标**（2026-08-24「天台县交能融合物流园跟踪审计中标公示」实证）。**全链路失败时**退回 WebSearch 限域兜底（`ggzy.zj.gov.cn`），且产物里必须标注「**该栏目直抓失败，本期依据搜索兜底，可能漏收**」——不得让读者以为已抓全。

# 三、周期性 / 事件触发（不占每日轮次）

# 推送规范（pushplus · 5G 消息 + 服务号 + 邮件）

> 本文件是 `tianxin-daily-brief` 推送环节的唯一权威说明。SKILL.md 只留调用入口，**改推送逻辑先改这里，再改 `push-notify.js`**。

日报生成并自检通过后，自动推送到三个终端：**① 天信负责人手机（中国移动 5G 消息）**、**② 微信「pushplus推送加」服务号**、**③ 245830958@qq.com（邮件）**。

---

## 一、三通道分工（内容不同，不可混用）

| 通道 | 参数 | 内容 | 定位 |
|---|---|---|---|
| 5G 消息 | `channel:"cmcc"`、`template:"txt"` | **要点压缩版纯文本**（编号 + 要点，默认 ≤420 字） | 三秒扫完，知道今天有没有要动的事 |
| 服务号 | `channel:"wechat"`、`template:"html"` | **移动端 HTML 看板**（全内联样式、单列重排，全部商机/热点/提示） | 微信里直接点开看，不必进邮箱 |
| 邮件 | `channel:"mail"`、`template:"html"` | **完整 HTML 看板**（桌面版式，全部字段、跟进建议、原文链接） | 存档与转发的正式版 |

**为什么短信只能是要点版**：`cmcc` 通道经中国移动「新消息ClawBot」应用号下发，正文过长会投递异常（实测 1732 字 / 4047 字节时手机端收不到正常正文，出现兜底回复）。故正文按优先级装入固定预算：**商机 > 天台县 > 提示 > 热点**，超预算的档位自动降级（见 `buildSmsText()` 的 6 级 `plans`），完整内容一律走服务号 / 邮件。

**不发布到任何公网**：GitHub Pages 路线已废弃——云端执行环境无 git 写凭据（`push` 必然失败），且 Pages 构建需数十秒到数分钟，链接发出时大概率 404。三个通道各自自带内容，都不依赖自建外链。

## 二、服务号看板为什么必须单独做一份（`buildWechatBoard()`）

`wechat` + `html` 的正文会被 pushplus **原样注入**详情页 `https://www.pushplus.plus/shortMessage/{id}` 的 `#messageContent` 容器。这个注入点有三条硬约束，直接复用桌面看板会翻车：

| 约束 | 后果 | 对策 |
|---|---|---|
| 注入点在 `<body>` 内的 div | 带 `<style>` 时，其中 `body` / `*` / `:root` 规则会外溢，**改写 pushplus 页面自身的标题栏与页脚** | 全量内联样式，**零 `<style>`** |
| 容器 `white-space: pre-line` | 内容里每个换行都渲染成空行，版面被撑散 | 输出前压掉所有换行（`replace(/\n/g,"")`） |
| 视口 ~375px | 桌面看板靠 `@media` 才降列，内联后 `@media` 失效、挤成四列 | 单列重排；速览与字段表用 `<table>` 保证对齐 |

内容与看板**同源抽取**（`matchBlocks` / `metaPairs` / `tagObjs`，与短信共用同一套选择器），不另行组织信息、不新增判断。超 2 万字上限时按 **跟进 → 相关性 → 热点条数** 六档收缩，并在末尾注明「余 N 条见邮件」，绝不整块丢板块。

**logo**：服务号版用**绝对地址**引用仓库原文件（`raw.githubusercontent.com/.../assets/tianxin-logo.svg`，仍是同一份官网原件，未做任何修改），并加 `onerror` 二级回退到 jsdelivr 镜像；白色底衬保证红章在 navy 页眉上不闷。

**版本体积参考**：2026-10-30 当日看板 → 桌面版 16,445 字符、服务号版 14,513 字符（全量档，未收缩）。

## 三、短信正文格式（`buildSmsText()` 生成）

```
天信每日日报 · 2026-10-30
商机 1｜天台县 0｜热点 7

【商机】
1. 台州市交通投资集团 2026-2028 年度财务报表审计 + …｜2026-11-05 09:00｜需联合

【天台县】
近 7 天无本县活单

【提示】
1. 交投集团 136 万/年审计 11-05 开标（倒计时 6 天）：天信无证券资格…
2. 新修改《注册会计师法》2027-01-01 施行，配套职业责任保险办法…

【热点】
1. 清越科技 3.7 亿赔付基金由谁承担，立信此前收取…
2. 深圳证监局对中审华行政处罚，暂停证券业务半年

完整版见服务号/邮件
```

**依赖的看板结构（生成看板时务必保持，否则抽取不到内容）**：
- `<section id="opportunities">` → `<div class="card">`（含 `<h4 class="c-title">`、`<dl class="meta">` 的 dt/dd、`<span class="tag">`、`<div class="follow">`）
- `<section id="hotspots">` → `<div class="news">`（含 `<h3 class="n-title">`）
- `<section id="tips">` → `<li><span class="t-body">`
- 速览区 `<div class="stat"><div class="n">…`（取天台县条数）
- 无 `c-title` 的卡片视为空列占位，自动跳过

**字数预算可由参数覆盖**：`buildSmsText(html, date, 420)`，第二参数即预算。若某天条目特别多，宁可降档也不突破 420。

## 四、调用方式（推荐 · 跨平台）

```bash
node references/push-notify.js "天信每日日报 · {日期}" "daily/{日期}.html"
```

- 助手读取看板 → 依次发三条：**5G 消息**（纯文本要点）→ **服务号**（移动端 HTML 看板）→ **邮件**（完整看板，`<style>` 内 `var(--x)` 全部落地）。
- 三通道各打印 HTTP 状态码、pushplus 返回与内容体检（字符数 / 收缩档 / `style` 与换行残留），并回显短信正文供核对。
- 本机 `curl` 因 Windows schannel 证书问题调不通 HTTPS，**统一用此 Node 助手**。

### 核验方式（推送后必做一次）
服务号返回 `data` 即消息 id，打开 `https://www.pushplus.plus/shortMessage/{data}` 核对：页眉 navy + 红章、三数速览、商机卡片数、热点条数、提示条数与看板一致，且**页面上方 pushplus 自身标题栏未被样式污染**。

### 凭证
- `PUSHPLUS_TOKEN` 环境变量优先；否则读同目录 `push-secrets.json`（`.gitignore` 已排除，绝不入库）的 `token` 字段。
- ⚠️ 公开仓库只保留 `push-config.example.md`（占位 token）。云端 agent 须设环境变量 `PUSHPLUS_TOKEN`。

### 接收端前置绑定（一次性，用户完成）
- 5G 消息：pushplus 个人中心 → 渠道配置 → 新消息ClawBot，绑定中国移动号码（发短信"绑定龙虾"到 12520098 授权）。
- 服务号：关注微信公众号「pushplus推送加」即默认接收（`channel:"wechat"` 走该服务号，无需额外配置）。
- 邮件：245830958@qq.com 须绑定到 pushplus 账号邮箱；若非 token 所有者本人，须加为好友并以 `to` 指定。

## 五、备选：curl（仅 Linux/云 agent 兜底）

> 不做「CSS 变量落地」「短信要点自动抽取」「服务号单列重排」，需手工准备 content；能用 Node 助手就用。

5G 消息（要点压缩版，≤420 字）：
```bash
curl -sS -X POST "https://www.pushplus.plus/send/${PUSHPLUS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"token":"'$PUSHPLUS_TOKEN'","title":"天信每日日报 · {日期}","content":"<编号+要点纯文本>","channel":"cmcc","template":"txt"}'
```
服务号（手搓移动端 HTML，**不带 `<style>`、不留换行**）：
```bash
curl -sS -X POST "https://www.pushplus.plus/send/${PUSHPLUS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"token":"'$PUSHPLUS_TOKEN'","title":"天信每日日报 · {日期}","content":"<全内联样式的HTML>","channel":"wechat","template":"html"}'
```
邮件（完整看板）：
```bash
curl -sS -X POST "https://www.pushplus.plus/send/${PUSHPLUS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"token":"'$PUSHPLUS_TOKEN'","title":"天信每日日报 · {日期}","content":"<HTML看板全文>","channel":"mail","template":"html"}'
```

- ⚠️ pushplus 单次 content 上限 2 万字：助手先压缩空白，超限按 `</section>` 硬截断并附说明（看板已无「历史参考」列，正常不触发）。
- 若 245830958@qq.com 非本人邮箱，改好友方式：`"to":"<对方pushplus账号>"`。
- 若运行环境已配置 Agent Mail，可直接把 HTML 日报发到该邮箱，不依赖 pushplus 邮件绑定。

## 六、纪律

- 仅当日报有实质内容时推送；空报告不推送。
- 5G 消息、服务号、邮件**分三次调用**，任一次失败不影响另外两次。
- 推送失败（HTTP 非 200 / 网络错误 / 接收端未绑定）**不阻断日报产出**，降级为「对话内完整呈现 + 记录失败原因（含返回 code/msg）」。
- 不推送任何未经负责人复核的对外承诺性内容。

## 七、故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 返回 `code:200` 但手机没收到 | 应用号未绑定 / 5G 消息未开通 | 让负责人按「绑定龙虾」流程重新授权 |
| 手机收到的是通用兜底话术（如"无法回答"） | **正文过长**，被应用号当成长问题处理 | 检查 `buildSmsText` 输出字数，压到 420 以内；必要时临时传更小预算 |
| 短信正文混入代码（`:root` / `var(--`） | 把 HTML 发给了 `txt` 通道 | 短信只发纯文本，绝不发 HTML |
| 服务号详情页排版全乱、pushplus 标题栏也被改色 | 服务号内容里带了 `<style>`（规则外溢到宿主页面） | 服务号必须走 `buildWechatBoard()`（全内联）；别把桌面看板直接发 wechat |
| 服务号详情页条目之间出现大片空白 | 内容里留了换行（容器 `pre-line` 逐行渲染） | 输出前 `replace(/\n/g,"")`；`check-dashboard.js` 第 6 项会拦 |
| 服务号详情页右侧出现横向滚动 | 桌面版式未降列（`@media` 在内联后失效） | 用单列模板；`<table>` 承载速览与字段表 |
| 服务号里 logo 显示为碎裂图标 | 图片域名在当前网络不可达 | `onerror` 已内置 jsdelivr 回退；两处都失败时检查仓库是否仍公开 |
| 服务号看不到内容 / 无推送 | 未关注「pushplus推送加」服务号 | 关注后重发；`channel:"wechat"` 无需额外绑定 |
| 邮件版式错乱 | CSS 变量未落地 | 用 Node 助手（会做 `resolveStyleVars`），别用 curl 直发 |
| `ERR` 网络错误 | 本机 HTTPS 证书问题 | 用 Node 助手，不用 curl |
